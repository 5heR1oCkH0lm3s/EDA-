# 第一部分 新人上手(把项目跑起来)

本文所有命令均在 **PowerShell** 中运行。Git 命令也可以在 Git Bash 中执行，但不要混用两个终端的路径和续行语法。

## 一、首次准备

1. 安装 Git，确认 `git --version` 能输出版本。
2. 在 Visual Studio Installer 中安装 **Visual Studio 2022 → 使用 C++ 的桌面开发**，包含 MSVC x64 工具、Windows SDK 和 C++ CMake 工具。
3. 准备 wxWidgets 3.2（本项目使用过 3.2.2.1）的 **x64 静态库，包含 Debug 库**。检查 `lib\vc_x64_lib` 下有 `wxmsw32ud_core.lib` 和 `wxbase32ud.lib`。

脚本优先使用 PATH 中的 CMake，也会查找 Visual Studio 自带 CMake，无需手动修改 PATH。仅能搜到 Visual Studio Installer 不代表 C++ 工具已经安装。

第一次获取项目（进入你准备放项目的父目录后执行）：

```powershell
git clone https://github.com/Pengyang-uestc/EDA-.git
Set-Location .\EDA-
```

已有项目不用再次克隆。例如本机仓库在 `E:\EDA task\EDA-repo`，进入它：

```powershell
Set-Location 'E:\EDA task\EDA-repo'
```

下文均以仓库根目录（含 `README.md` 和 `build.bat`）为执行目录。

## 二、首次编译

双击 `build.bat`，或在 PowerShell 中执行：

```powershell
.\build.bat
```

脚本查找 wxWidgets 的顺序为：`-Wx` 参数、`WXWIN` 环境变量、课程资料的几个常见目录。找不到时手动指定实际路径：

```powershell
.\build.bat -Wx 'E:\你的工具目录\wxWidgets-3.2.2.1'
```

想让以后双击也能找到：在 Windows“编辑账户的环境变量”中新建用户变量 `WXWIN`，值填 wxWidgets 根目录（不是 `lib` 子目录），然后重新打开终端；若从资源管理器双击仍未生效，注销并重新登录 Windows。

脚本会配置工程、编译程序、编译测试、运行测试。看到 `ALL PASS` 且最后显示“编译和测试全部通过”才是成功。任一步失败会返回非零退出码，并停止后续步骤。

`-Clean` 使用 CMake 的 `--clean-first` 重新编译，不删除整个 build 文件夹，也不重置 CMake 缓存；平时无需使用。

## 三、运行与示例

双击 `MyEDA\build\Debug\MyEDA.exe`。首次编译前此文件不存在。

程序中选择“文件 → 打开”，打开 `examples\half_adder\half_adder.eda`，按 F5 仿真，点击开关观察灯；按 F6 停止仿真后再编辑。

也可以从仓库根目录直接带文件启动：

```powershell
.\MyEDA\build\Debug\MyEDA.exe .\examples\half_adder\half_adder.eda
```

## 四、日常选哪个入口

| 场景 | 操作 |
|---|---|
| 拉取当前分支的远程更新并运行 | 先保存电路、关闭 MyEDA，再双击 `update-and-run.bat` |
| 修改了代码，想验证本地效果 | 关闭 MyEDA，双击 `build.bat`，通过后打开 exe |
| 没有更新，也没有修改源码 | 直接打开 exe，无需重新编译 |

更新入口自动执行 `git pull --ff-only`、编译、测试和启动；只更新**当前分支的上游**，不会自动切换 main，也不会把 main 合入功能分支。存在未提交修改（包括未跟踪文件）、缺少上游、分支分叉或网络错误时会停止。已经拉取但编译失败时，源码会保留在更新后的版本，程序不会启动。

需要手动指定依赖时：

```powershell
.\update-and-run.bat -Wx 'E:\你的工具目录\wxWidgets-3.2.2.1'
```

关于修改代码、首次推送与合并，请阅读《四人协作指南》（`docs/开发协作/四人协作指南.md`）。

| 提示或现象 | 处理 |

| 拉取网络失败 | 检查 GitHub 连接后重试；无需删除仓库重新下载 |
| 教程合集检查失败 | 修改分篇文档后重新运行 `python .\tools\merge_docs.py` |

## 1. 界面速览(五个区)

工具栏图标与文字横向排列，画布使用 10 像素细网格、50 像素主网格。新放置与拖动的元件、连接引脚和路径拐点均吸附到网格。

```
┌──────────────────────────────────────────────────────────┐
│ 菜单栏:文件 编辑 工程 仿真 窗口 帮助                        │
├──────────────────────────────────────────────────────────┤
│ 工具栏:[新建][打开][保存] | [选择][连线][删除] | [与][或][非] | [仿真] │
├──────────┬──────────────────────────────┬────────────────┤
│ 元件库树  │        绘图区(画电路)         │    属性表       │
│ (左,固定) │        (中间,占满)            │   (右,固定)     │
├──────────┴──────────────────────────────┴────────────────┤
│ 状态栏:左格=最近的操作提示    右格=当前工具/选中提示          │
└──────────────────────────────────────────────────────────┘
```

- **元件库树**:`基本门电路`(与/或/非/异或/与非/或非门)、`输入/输出`(开关/指示灯)、`自定义元件`(＋新建 + 你定义过的元件)
- **属性表**:点中画布上一个元件,这里立即显示 名称/类型/位置/输出(自定义元件还显示 4 行真值表);选中多个时显示汇总
- **状态栏**:左格告诉你刚做了什么(如"已保存""已撤销"),右格显示当前工具

## 3. 编辑菜单与鼠标操作

### 菜单项

| 菜单项 | 快捷键 | 说明 |
|---|---|---|
| 撤销 | Ctrl+Z | 回退上一步(最多 100 步);状态栏显示"已撤销"或"没有可撤销的操作" |
| 重做 | Ctrl+Y | 恢复被撤销的一步 |
| 剪切 | Ctrl+X | 复制并删除选中元件 |
| 复制 | Ctrl+C | 复制选中元件及它们之间的内部连线(可多个，含拐点) |
| 粘贴 | Ctrl+V | 粘贴到原位置右下 30 像素处,**自动分配新编号并选中** |
| 删除 | Delete | 删除选中元件;**挂在它上面的连线一起删掉**。⚠️ 删不掉时看状态栏:没选中元件会提示"请先点选元件(变蓝框)";仿真运行中会提示"先停止仿真" |
| 全选 | Ctrl+A | 选中画布上所有元件 |

### 鼠标操作(四种模式,由工具栏切换)

**放置模式(默认,或点工具栏"与/或/非门")**
- 点画布空白处 → 放一个当前类型的元件(选中树里的元件类型也可以)
- 点已有元件 → 选中它(蓝框),按住拖动 → 移动
- **Shift 或 Ctrl + 点元件** → 加选 / 取消选中

**选择模式(点工具栏"选择")**
- 在空白处按住拖动 → 拉出蓝色虚线框,**框到的元件全部选中**(框选)
- Shift/Ctrl + 拖 → 追加框选(保留原来的选中)
- 点空白处 → 清空选择
- 选中后拖动任一元件 → **整组一起移动**
- 按 Esc → 取消所有选择

**连线模式(点工具栏"连线")**
- 点第一个引脚(引脚周围小范围算命中) → 出现灰色虚线跟着鼠标(预览)
- 点目标引脚 → 完成一根连线;可以继续连下一根
- 点空白网格 → 添加一个路径拐点，可以连续添加多个；拐点吸附到 10 像素网格
- 点目标引脚 → 完成整条直角折线；不设拐点时自动生成水平/垂直连接段
- 按 Esc → 取消当前预览线，仍可重新选择起点；切换工具也会清除预览
- 预览采用双缓冲和静态画布缓存，移动鼠标时只刷新新旧预览线覆盖的区域

**仿真模式(点工具栏"仿真"或菜单"开始仿真")**
- 点开关元件 → 切换 0/1 并**立即重算整个电路**
- 高电位导线画红色,低电位画黑色;LED 亮=红、灭=白
- 再点一次"仿真"或按 F6 停止(停止后不再显示电位颜色)

> **属性表随时联动**:无论选中、拖动、撤销、粘贴,右侧属性表都会跟着变。

## 4. 工程菜单

### 新建工程
清空画布开始一份新电路(与"文件→新建"相同)。

### 新建自定义元件(用真值表定义一个新元件)

1. 菜单 **工程 → 新建自定义元件**
2. 在弹出的对话框里:
   - **元件名称**:给元件起个名字(如 `MYAND`)
   - **真值表**:4 个勾选框,分别对应 4 种输入组合
     - 勾选框 1 = A=0,B=0 时的输出
     - 勾选框 2 = A=0,B=1
     - 勾选框 3 = A=1,B=0
     - 勾选框 4 = A=1,B=1
     - **勾上 = 该组合下输出 1,不勾 = 输出 0**
3. 点"确定" → 元件会出现在左侧树的 `自定义元件` 分支下,并**自动进入放置模式**
4. 在画布上点一下就放下去了

> **为什么 4 个勾选框能定义任意逻辑?** 2 输入 1 输出的元件一共只有 4 种输入组合,
> 每种组合输出 0 还是 1 定完,行为就唯一确定了。例如勾第 4 个(只有 A=1,B=1 输出 1)就是"与门"。

### 管理自定义元件

1. 菜单 **工程 → 管理自定义元件**
2. 列表里显示所有已定义元件及其真值表(如 `MYAND [真值表 0001 (00,01,10,11)]`)
3. 三个按钮:
   - **新建**:同上面的定义流程
   - **编辑**:改名字或改真值表;**画布上已放置的同名元件会一起更新**(这一步可以撤销)
   - **删除**:只删掉"定义"（可撤销，并触发未保存提醒），**画布上已经放好的元件保留不动**(它们自带名字和真值表)
4. 关闭对话框后,左侧树会自动刷新

> 自定义元件库会**跟着电路一起存进 `.eda` 文件**,下次打开文件时自动恢复。

## 5. 仿真菜单

| 菜单项 | 快捷键 | 说明 |
|---|---|---|
| 开始仿真 | F5 | 计算整个电路并着色:导线红=高电位、黑=低电位;LED 亮/灭 |
| 停止仿真 | F6 | 结束仿真显示,恢复正常配色 |

**仿真时能做什么**:点开关切换状态 → 立即重算;**仿真运行中不能选中/移动/删除元件**
(点非开关元件会提示"仿真运行中…"——先点"停止仿真"或 F6,再进行编辑操作)。

**仿真结果怎么算出来的**:
- 开关输出 = 自己的开关状态(0/1)
- 与/或/非/异或/与非/或非门 = 各自的逻辑运算
- **自定义元件 = 查它自己的真值表**
- 悬空输入按 0 处理

## 8. 文件格式

### 8.1 工程文件 `.eda`(JSON 文本,可以记事本打开看)

```json
{
  "components": [
    {"id":1,"type":"SW","x":200,"y":250,"state":1,"name":"","truth":0},
    {"id":3,"type":"CUSTOM","x":480,"y":340,"state":0,"name":"MYAND","truth":8},
    {"id":5,"type":"LED","x":700,"y":340,"state":0,"name":"","truth":0}
  ],
  "wires": [
    [1,0,3,0],
    [3,2,5,0]
  ],
  "customGates": [
    {"name":"MYAND","truth":8}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `id` | 元件编号(显示为 U1、U2…) |
| `type` | `AND`/`OR`/`NOT`/`XOR`/`NAND`/`NOR`/`SW`/`LED`/`CUSTOM` |
| `x`,`y` | 画布坐标(像素) |
| `state` | 开关的开/关 |
| `name`,`truth` | 自定义元件的名字与真值表(其他类型为空) |
| `wires` | 每根线 4 个数:`[起点元件, 起点引脚, 终点元件, 终点引脚]` |
| `customGates` | 自定义元件库(名字 + 真值表) |

**引脚编号约定**:与/或/异或/与非/或非/自定义门 `0=上输入 1=下输入 2=输出`;非门 `0=输入 1=输出`;开关/指示灯只有一个引脚(编号 0)。

### 8.2 网表文件 `.net`(KiCad 6+ 的 S 表达式)

导出后可以用记事本打开,结构是 `(design …) (components …) (libparts …) (nets …)` 四段。要点:

- **每个元件带封装**(否则 KiCad 导入时报"没有分配封装"):门=`Package_DIP:DIP-14_W7.62mm`、开关=`Button_Switch_THT:SW_PUSH_6mm`、灯=`LED_THT:LED_D5.0mm`
- **引脚从 1 开始编号**(和 PCB 焊盘编号对应)
- **一根连线不等于一个网络**:一个输出接多个输入时,程序会把这些引脚合并成一个网络(否则 PCB 软件会当短路报错)
- 网络名形如 `Net-(U1-Pad1)`,与 KiCad 自己的命名习惯一致

### 8.3 KiCad 原理图 `.kicad_sch`

导出后可在 KiCad 里直接打开(工程文件 `.kicad_pro` 已在样例里提供),按 **F8** 即可"从原理图更新 PCB"。

## 11. 已知限制(诚实说明)

1. **与/或/异或/与非/或非门和自定义元件为 2 输入、1 输出**；非门为 1 输入、1 输出，开关只有输出、指示灯只有输入。需要 3 输入逻辑时可用两级门级联
2. **逻辑门和开关各有 1 个输出引脚，指示灯没有输出**；输出可以接多个输入(扇出支持)
3. **没有总线、三态门、时钟/触发器**等时序元件(课程要求范围内)
4. **网表不含坐标和开关状态**,所以导入网表后元件会重新排布、开关默认关
5. **没有封装管理器**:默认封装是为演示"能进 PCB"准备的,真实设计应在 KiCad 里按实际器件改
6. **视图支持缩放和平移**：滚轮以鼠标位置为中心缩放，中键拖动平移，Ctrl+0 或“窗口 → 复位视图”恢复原点和 100%

### 直角连线保存说明

`.eda` 保留原有 `wires` 四元组，新增可选 `wireRoutes` 字段记录每条线的拐点。旧工程没有此字段也能打开，并自动显示直角路径。网表只保存电气连接，不包含拐点布局；KiCad 原理图导出使用其自己的布局。线段交叉不自动产生电气连接。移动元件时固定的手动拐点保留，端点连接段自动调整为直角。


## 展示前完善的编辑与保护功能

- 连线可先点输入或先点输出，系统统一为输出 → 输入。输入接输入、输出接输出、重复占用输入和组合逻辑反馈环会被拒绝，并在状态栏说明原因。
- “选择”工具下点击线段可选中整条线，按 Delete 删除；Ctrl+Z 撤销删除。复制多个元件时，会同时复制它们之间的连线和拐点；外部连接不会随复制带走。
- 自定义元件定义的新增、改名、真值表修改、删除都支持撤销重做，并参与未保存提醒。加载另一份工程时，元件库替换为该工程的定义。
- 工程文件按 JSON 结构、字段类型、元件编号、引脚和连接关系校验；异常文件被拒绝，原电路保留。保存采用临时文件提交，避免直接覆盖过程中丢失原文件。
- 网表导入先校验格式和引用；数字逻辑网络按输出端向各输入端重建，可继续仿真。自定义器件的真值表无法由普通网表恢复，需要自行设置。
- 滚轮缩放范围为 40%～300%，中键拖动画布平移，Ctrl+0 复位视图；视图变化不修改工程数据。

### A —— 界面模块

#### 我要讲的(讲稿提纲)
> "整个界面我用 wxWidgets 的 sizer 布局搭成一栏三块:左边元件库树、中间绘图区、右边属性表,上面是菜单和工具栏。五个元素对应任务 2 的要求。**最关键的一点是属性表怎么知道该刷新** —— 我没有让主窗口去轮询,而是让绘图区在内容变化时**回调**通知主窗口,这样两者不互相依赖。"

#### 关键代码位置
- 三栏布局:`MyFrame::CreateClientArea()`
- 菜单/工具栏/状态栏:`CreateMenuBar()` / `CreateToolBar()` / `CreateStatusBar()`
- 属性表刷新:`MyFrame::RefreshPropertyTable()`
- 回调注册:`canvas->SetSelectionCallback([this](){ ... })`
- 自定义元件对话框:`CustomDialog::CustomGateDialog` / `CustomManagerDialog`
- 未保存提醒:`MyFrame::ConfirmDiscardChanges()` / `OnClose()`

#### 为什么这么写(可能被追问)
1. **sizer 布局而不是写死坐标**:窗口拉伸时布局自动适配(比例 0 = 固定宽,比例 1 = 吃掉剩余空间)
2. **回调而不是轮询**:轮询浪费 CPU 且难维护;回调是"内容变了打电话通知",方向是画布→主窗口,画布不需要知道主窗口是谁
3. **对话框只记录操作、不直接改数据**:管理自定义元件对话框只把用户操作记成"动作清单",关闭后由主窗口统一执行——职责清晰,也好测

#### 理解与验证练习(练习记录不等于历史开发贡献)
- 在"帮助"菜单加一项"使用说明",弹出 `wxMessageBox`

### B —— 数据模型与绘图编辑

#### 我要讲的(讲稿提纲)
> "全组的数据基础是我定义的两个结构:元件 `Component` 和连线 `Wire`。原则是**数据是核心,界面只是把数据画出来**。绘图区的交互有三块:命中测试、拖动、连线。命中测试是从后往前比包围盒,因为后画的元件在上面;拖动我记录每个选中元件相对鼠标的偏移,松手时若真的移动过才记一步撤销;连线先记录起点，移动时画直角预览，空白处可添加多个拐点，点目标引脚后经方向和合法性检查才提交整条连线。"

#### 关键代码位置
- 数据结构:`Component.h` 的 `struct Component` / `struct Wire` / `GetPinPos()`
- 画图:`DrawingCanvas::OnPaint()`,元件符号 `DrawGate()`
- 命中:`HitTest()`(元件)、`HitPin()`(引脚)
- 拖动:`OnLeftDown()` 记录偏移 → `OnMotion()` 平移 → `OnLeftUp()` 提交撤销快照
- 连线:`OnLeftDown()` 里的两步点击逻辑 + `OnPaint()` 里的橡皮筋预览
- 删除级联:`DeleteSelected()`(删元件同时删掉挂在它身上的连线)
- 多选:`std::set<int> sel` + `InRect()` 框选 + `SelectAll()`
- 撤销:`PushUndo()` / `Undo()` / `Redo()`(存 JSON 快照)

#### 为什么这么写
1. **连线存"元件编号+引脚号"而不是坐标**:所以移动元件时连线自动跟着走——`OnPaint` 每次现算引脚位置
2. **快照式撤销**:不为每种操作写"反操作",改动前存一段电路 JSON,撤销就是读回旧文本。一份代码覆盖放置/删除/拖动/连线/粘贴
3. **拖动只在真的移动过才记撤销**:比较开始和结束的快照,避免"点一下就选中"污染撤销链

#### 我改过什么
- 把画布网格间距从 25 改成 40(`DrawingCanvas::OnPaint` 里两处)
- 给一种门换个颜色,或把选中描边从蓝色改成红色

### C —— 文件、网表与 KiCad 对接

#### 我要讲的(讲稿提纲)
> "我负责'数据出得去、进得来'。有两套格式:一套是我们自己的工程文件 `.eda`,用 JSON 存元件和连线,还有自定义元件库;**写文件严格、读文件宽容**——新增字段用可选解析,旧文件照样能打开。另一套是给 PCB 软件用的**网表**:网表是电路的电气描述,谁和谁相连。这里有两个技术点:第一,**一根连线不等于一个网络**——一个输出接多个输入(扇出)时要用并查集把电气连通的引脚归成一个网络,否则同一个引脚出现在两个网络里,PCB 软件会当短路报错;第二,**格式必须和 KiCad 自己导出的完全一致**,我的做法是让 KiCad 自己导一份参考网表,逐字段对比,连封装字段写在哪都对齐了。"

#### 关键代码位置
- 存档:`CircuitFile.h` 的 `CircuitToJson` / `JsonToCircuit` / `SaveCircuit` / `LoadCircuit`
- 网表导出:`NetlistExport.h` 的 `ExportKiCadNetlist`
- **扇出合并**:`BuildNets()`(并查集)
- 网表导入:`ParseKiCadNetlist()`
- 默认封装:`DefaultFootprint()`,引脚电气类型:`PinTypeOf()`
- KiCad 原理图导出:`KicadSchExport.h` 的 `ExportKicadSchematic()`

#### 为什么这么写(被追问时的高分点)
1. **写严格读宽容**:这是工程惯例(Postel 定律)。我们后来给存档加了 `name`/`truth` 字段,因为解析用可选组,老文件仍然打得开
2. **并查集**:连线是多对多的关系,要算"电气上连通的一组引脚",并查集是最标准的做法;顺带保证每个引脚只属于一个网络
3. **对齐真实格式的方法论**:不靠猜,让 KiCad 自己导一份出来对比。我们因此发现:封装必须写在**紧跟 `(value ...)` 的 `(footprint ...)` 元素**里,写在 `fields` 里那份只是给人看的——这个坑不对比根本发现不了
4. **坐标用纳米整数算**:导出原理图时,引脚位置和导线端点都由同一组整数算出,保证在 KiCad 里严丝合缝能连上

#### 我改过什么
- 改 `DefaultFootprint()` 里门的封装名,重新导出网表看变化
- 用命令行工具导出/解析:`test_sim.exe --export-netlist` / `--parse-netlist`
- 给存档加一个字段(比如版本号),验证旧文件还能读

1. 文件 → 导出网表 → 保存 → 用记事本打开看结构
2. 打开 `examples/half_adder/` 展示四件套:`.eda`(我们工程)、`.net`(网表)、`.kicad_sch`(原理图)、`.kicad_pcb`(KiCad 生成的 PCB)
3. (加分)现场打开 KiCad → PCB 编辑器 → 文件→导入→网表 → 选 `.net` → 点"加载并测试" → **错误 0**

### D —— 仿真引擎、测试与整体验收

#### 我要讲的(讲稿提纲)
> "我负责两件事:算逻辑和证明它对。仿真算法是**迭代传播**:初始化时开关等于自身状态、门输出都当 0;然后一轮一轮让每个门读输入算输出,重复'元件个数+2'轮,信号一定能从开关传到最远的灯。自定义元件用**真值表**驱动——2 输入 1 输出一共只有 4 种组合,用 4 个二进制位就能描述任意逻辑。验证方面,我们写了一个不开界面的单元测试程序,**64 项检查全部通过**,包括真值表、存档往返、网表往返、以及用 KiCad 真实导出的网表做互操作测试。最终验收是半加器:两个开关、异或门做'和'、与门做'进位',四种输入组合都对得上。"

#### 关键代码位置
- 仿真:`Simulation.h` 的 `SimulateCircuit()`(迭代传播)、`FindSource()`(沿线找来源)
- 单元测试:`test/test_sim.cpp`,命令行运行
- 导线着色/灯:`DrawingCanvas::OnPaint()` + `GetPinValue()`
- 半加器样例:`examples/half_adder/half_adder.eda`

#### 为什么这么写
1. **为什么迭代 `元件数+2` 轮**:组合逻辑没有环,信号最长路径不超过元件数,多加两轮保证稳定;不需要递归也不用拓扑排序,新手好懂
2. **为什么引擎写成不碰界面的纯函数**:能单元测试。GUI 测试很脆(对话框、输入法、窗口焦点都会捣乱),但纯函数可以用命令行 1 秒验证 64 项
3. **真值表位序**:第 i 位对应输入组合 i,其中 `i = A*2 + B`;所以与门 = `0b1000` = 8,与非门 = 7

#### 我改过什么
- 加一条测试用例(比如验证非门),跑 `test_sim.exe` 看到新增的 PASS
- 改一个门的真值表值,看测试失败(体验"测试真的在管用")

1. 打开半加器 → 点"仿真"→ 点开关 A/B,看两个灯(和、进位)变化,报真值表

## 5. 老师可能问的 20 个问题 + 参考答案

**通用类**

1. **你们的数据结构是什么?**
   两个结构:元件 `Component`(类型/坐标/编号/开关状态/自定义元件名与真值表)和连线 `Wire`(起点元件+引脚 → 终点元件+引脚)。存盘、网表、仿真都基于它们。

2. **为什么用 C++ 和 wxWidgets?**
   课程要求用 wxWidgets 做界面;C++ 性能好、能直接操作底层绘图,适合做 EDA 工具。

3. **一共多少代码?怎么分工的?**
   自研代码约 2800 行,按文件边界分四块:界面、编辑、文件网表、仿真验证。

**界面类**

4. **五个界面元素怎么布局的?**
   用 `wxBoxSizer` 横向三栏:树(固定宽) + 绘图区(占满剩余) + 属性表(固定宽);菜单和工具栏由 `wxFrame` 提供。

5. **属性表怎么知道选中了哪个元件?**
   画布有一个回调 `SetSelectionCallback`,选中/拖动/撤销等任何变化都会调用它,主窗口在回调里刷新属性表。这样画布不需要知道主窗口的存在。

6. **绘图区是现成控件吗?**
   不是。wxWidgets 没有电路图控件,我们继承 `wxPanel` 自己写,在 `wxEVT_PAINT` 里用 `wxPaintDC` 画网格、连线、元件符号。

7. **元件符号怎么画的?**
   与门用直线+弧线拼成 D 形,或门/异或门用 `DrawPolygon` 折线画弯月形,非门是三角形+小圆,自定义元件是方框+名字(一开始或门用弧线画,角度方向很难控,改成折线一次成功)。

**编辑类**

8. **怎么判断鼠标点到了哪个元件?**
   `HitTest`:从后往前比较鼠标坐标是否落在元件的包围盒里。从后往前是因为后画的在上层,应该先被选中。

9. **拖动是怎么实现的?**
   按下时记录鼠标相对元件中心的偏移,移动时用"鼠标位置 − 偏移"反算中心,这样元件不会跳;拖动多个元件时对每个元件各记一份偏移。

10. **连线怎么实现?**
    两步状态机:第一次点引脚记住起点,移动时画虚线预览,第二次点引脚生成一根 `Wire`。删除元件时会级联删掉挂在它上面的连线,避免悬空引用。

11. **撤销怎么做的?**
    快照式:每步改动前把当前电路序列化成 JSON 文本压栈,撤销就是弹出并读回。好处是不用为每种操作写反操作,一份代码覆盖所有操作。

**文件与网表类**

12. **你们的工程文件格式是什么?**
    JSON 文本,包含 `components`(元件)、`wires`(连线)、`customGates`(自定义元件库)三段。存盘重开、往返一致。

13. **网表和工程文件有什么区别?**
    工程文件是"画图信息"(坐标、颜色…),网表是"电气信息"(谁和谁相连),后者才是 PCB 软件要的。

14. **为什么一根连线不等于一个网络?**
    一个输出常常接多个输入(扇出)。画面上是两根线,电气上是同一个网络。我们用并查集把连通的引脚归并成一个网络,否则同一个引脚会出现在两个网络里,PCB 软件会当成短路冲突。

15. **怎么保证网表 KiCad 能认?**
    让 KiCad 自己导出一份参考网表,逐字段对比我们的输出,连"封装字段写在哪"都对齐了。最终在 KiCad 里导入:**错误 0**,并生成了 PCB 文件(6 个封装、4 个网络,网络名就是我们生成的 `Net-(U1-Pad1)`)。

16. **封装(footprint)是什么?**
    元件在 PCB 上的实际形状:几个焊盘、焊盘怎么排布。没有封装,PCB 软件不知道元件怎么摆、没法布线。我们给门/开关/灯分别指定了 KiCad 标准库里的默认封装。

**仿真与测试类**

17. **仿真怎么算的?**
    迭代传播:初始化开关状态和门输出,然后重复"元件数+2"轮,每轮让每个门读输入算输出。信号一定能传到最远的灯。

18. **自定义元件的原理?**
    2 输入 1 输出的逻辑一共只有 4 种输入组合,用 4 个位就能描述任意逻辑。用户勾 4 个复选框就是填真值表,仿真时按输入组合查表。

19. **你们怎么测试的?**
    三层:① 单元测试(64 项,命令行跑,验证真值表/存档往返/网表往返/解析);② GUI 自动化(脚本模拟真实点击拖动,比对保存出来的文件);③ 端到端验收(半加器真值表 + KiCad 导入)。

20. **遇到过什么困难?怎么解决的?**
    三个例子:① 或门的弧线方向很难控,改成折线一次成功;② 网表格式自己觉得对但 KiCad 报错,改用"让 KiCad 导参考网表逐字段对比"的方法解决;③ 程序启动崩溃,用二分法(先去掉一半代码试试)定位到"界面初始化顺序"问题。

# 第四部分 实现讲解(每个功能为什么这么写)

> 这份文档写给"刚学 C++ 和 wxWidgets"的组员。每个功能都讲三件事:
> **它是什么 → 为什么这么写 → 代码在哪儿**。

---

## 0. 先记住一句话

> **数据是核心,界面只是把数据"画"出来。**

这句话贯穿整个项目。下面是我们的"数据":

```cpp
struct Component {      // 一个元件
    GateType type;      //   什么门(与/或/非/异或/与非/或非/开关/灯/自定义)
    int x, y;           //   画在哪儿
    int id;             //   编号(显示成 U1、U2...)
    bool state;         //   开关的开/关
    wxString customName;//   自定义元件的名字
    int truth;          //   自定义元件的真值表
};

struct Wire {           // 一根连线
    int comp1, pin1;    //   起点:哪个元件、哪个引脚
    int comp2, pin2;    //   终点
};
```

画布上所有东西,就是"一个元件列表 + 一个连线列表"。

## 3. 本轮补齐的三个功能(重点)

这三件事之前"有壳无实":控件都在、菜单项都在,但点下去没真功能。

### 3.1 属性表:回调函数让画布"打电话"

**问题**:属性表在主窗口(`MyFrame`)里,但"选中了哪个元件"这个信息在画布(`DrawingCanvas`)里。主窗口怎么知道该刷新了?

**笨办法**:主窗口定时轮询("你选了吗?你选了吗?...") —— 浪费、别扭。

**我们的办法**:**回调**。画布留一个"电话号码",任何变化时拨一下:

```cpp
// DrawingCanvas.h —— 画布说:"谁想被通知,就把函数给我"
std::function<void()> onSelection;
void SetSelectionCallback(std::function<void()> cb) { onSelection = cb; }

// DrawingCanvas.cpp —— 内容一变就拨号
void DrawingCanvas::NotifyChanged()
{
    InvalidateScene();               // 标记静态图需要重建，再请求重画
    if (onSelection) onSelection();  // 打电话给主窗口
}
```

```cpp
// MyFrame.cpp —— 主窗口登记自己的号码
canvas->SetSelectionCallback([this]() { RefreshPropertyTable(); });
```

`[this]() { ... }` 是 **lambda 表达式**(匿名函数),`[this]` 表示"我要用当前对象的成员"。

**关键设计**:画布只知道"有人要通知我",**不知道**是谁 —— 所以画布不依赖主窗口。这个方向叫"依赖倒置",是解耦的常用手法。

**效果**:选中/拖动/仿真/撤销/粘贴……任何变化,属性表都自动刷新。属性表显示:
名称、类型(自定义元件显示"自定义(名字)")、位置、状态/输出,自定义元件还多 4 行真值表。

### 3.2 撤销/重做:存快照,别写"反操作"

**问题**:怎么实现撤销?

**笨办法**:为每个操作写一个"反操作" —— 放置的反操作是删除、删除的反操作是"记住删了什么再放回去"、拖动的反操作是"记住原来在哪再拖回去"、连线的反操作是删线……
每种操作都要写两遍代码,又多又容易错。

**我们的办法**:**快照式**。因为我们已经验证"电路 → JSON 文本 → 电路"是无损的,所以:

> 每步改动之前,先把当前电路存成一段 JSON 文本压进栈;
> 撤销 = 把栈顶那段旧文本读回来。

```cpp
void DrawingCanvas::PushUndo()                 // 改动前调用
{
    undoStack.push_back(CircuitToJson(components, wires));
    if (undoStack.size() > 100) undoStack.erase(undoStack.begin()); // 只留最近100步
    redoStack.clear();                          // 有了新动作,重做链失效
}

bool DrawingCanvas::Undo()
{
    if (undoStack.empty()) return false;
    redoStack.push_back(CircuitToJson(components, wires)); // 当前状态留给"重做"
    wxString snap = undoStack.back(); undoStack.pop_back();
    RestoreSnapshot(snap);
    return true;
}
```

**两个细节**:
- **拖动**:只在按下时存快照,松手时比较"内容变了没",没变就不入栈 —— 否则"点一下选中"这种没有改动的动作也会污染撤销链。
- **栈深 100**:上限,防止长时间使用内存无限增长。

**这个思路的价值**:一份代码覆盖所有操作(放置/删除/拖动/连线/粘贴),以后加新操作也不用改撤销逻辑。

### 3.3 用户自定义元件:4 个复选框 = 一张真值表

**任务要求**:"支持用户自定义元件"。之前只有写死在代码里的与/或/非门,用户没法自己造。

**核心洞察**:**2 输入 1 输出的逻辑电路,行为完全可以由真值表描述**。
一共只有 4 种输入组合(A=0B=0 / A=0B=1 / A=1B=0 / A=1B=1),
每种组合的输出是 0 还是 1,4 个勾选框就能定完 —— **这样就能定义任意 2 输入逻辑!**

我们把这张表打包成一个整数存起来(位运算):

```
truth 的二进制位    bit3 bit2 bit1 bit0
对应的输入组合      (1,1)(1,0)(0,1)(0,0)      ← 组合编号 i = A*2 + B
例:与门             1    0    0    0     = 8
例:与非门           0    1    1    1     = 7
```

```cpp
// 仿真时:算出输入组合编号 i,取 truth 的第 i 位
else if (c.type == GATE_CUSTOM) {
    int idx = v0 * 2 + in(c, 1);   // v0=输入引脚0的值,in(c,1)=引脚1的值
    res = (c.truth >> idx) & 1;    // 取第 idx 位
}
```

**数据怎么流动**(整个功能的链路):

```
用户勾真值表        → 自定义元件对话框(CustomDialog.h)
  → 存进 customDefs 列表,并在元件库树上挂一个节点
  → 点击该节点 → 画布进入"放置模式",记住名字和真值表
  → 点击画布 → 生成一个 type=CUSTOM 的 Component(带 name+truth)
  → 存盘时 name/truth 一起写进 JSON
  → 读盘时一起读回来(老文件没有这两个字段也能读,见 3.4)
```

**顺带一提**:网表里自定义元件只写它的**名字**(不写真值表)。
这跟真实 EDA 软件一致 —— 网表只说"这里用了某某型号的元件",具体行为由元件库提供。

### 3.4 写严格、读宽容

给存档新增 `name`/`truth` 字段后,老存档(没有这两个字段)就解析失败了。
**这是绝对不能接受的**:用户之前存的文件必须还能打开。

解决:正则里把新字段写成**可选组**,读的时候判断"匹配到了没":

```cpp
// (,"name":"...","truth":N)?  ← 问号表示"可有可无"
std::regex compRe("...\"state\":(\\d)(,\"name\":\"([^\"]*)\",\"truth\":(\\d+))?...");
// 读的时候:
c.customName = (*it)[7].matched ? ... : wxString();   // 没匹配到就用默认值
c.truth      = (*it)[8].matched ? std::stoi((*it)[8]) : 0;
```

工程界把这叫 **Postel 定律**:"发送时要保守,接收时要宽容"。
越界的输入、旧版本的文件,都尽量兼容 —— 否则你的软件会三天两头"打不开文件"。

## 3.4 网表:一根线 ≠ 一个网络(一个重要修正)

**先讲背景**:一开始我们把"每根连线 = 一个网络"直接写进了网表。

**问题出在"扇出"**:一个输出接多个输入是电路里的常态。半加器里开关 `SW_A`
同时接到 XOR 和 AND,我们画了 **2 根线**,但电气上它们是**同一个网络**。
按老写法,`U1` 的引脚 1 会出现在**两个网络**里 —— PCB 软件看到"同一个焊盘属于两个网络",
会当成短路/冲突报错。**网表是给机器读的,语义错了它不会给你面子。**

**正确做法**:把"连线"归并成"电气网络"。用**并查集**(union-find):

> 每根连线把两端"合并到同一组";最后同一组的引脚就是一个网络。

```
画布上的连线                     并查集归并后的网络
U1[0] -- U3[0]                  net1: U1[0] + U3[0] + U4[0]   ← 3 个节点
U1[0] -- U4[0]        ==>       net2: U2[0] + U3[1] + U4[1]   ← 3 个节点
U2[0] -- U3[1]                  net3: U3[2] + U5[0]
U2[0] -- U4[1]                  net4: U4[2] + U6[0]
...
```

导入时反过来做:一个网络有 N 个节点 → 重连成 N-1 根线(链式),电气上等价。
**必须"块内配对"**:把所有节点拉平再两两配对,会把上一个网络的节点和下一个网络的
节点连到一起 —— 这是我们真实踩过的 bug,现在单元测试里专门盯着它。

## 3.5 让网表真的"能被 KiCad 加载"(对齐真实格式)

任务要求"导出标准网表文件,该文件能够被 PCB 软件加载"。光靠自己"觉得对"不算数,
我们做了三件事:

**第一件:让 KiCad 自己导出一份参考网表,逐字段对比。**
用 KiCad 的命令行工具,从一张最小原理图导出网表:

```bash
kicad-cli sch export netlist --format kicadsexpr -o ref.net ref.kicad_sch
```

对比后发现我们少了 4 样东西,全部补齐:

| 项目 | KiCad 的写法 | 为什么要紧 |
|---|---|---|
| 网络分组 | `(net ... (class "Default"))` | PCB 软件靠 class 套用线宽/间距规则 |
| 节点电气类型 | `(node ... (pintype "input"))` | 告诉 PCB 软件这个脚是输入还是输出 |
| 引脚编号 | 从 **1** 开始 | 必须和 PCB 焊盘的编号(Pad 1、2、3)对得上,否则连不上 |
| 元件库段 | `(libparts (libpart ...))` | PCB 软件从库里取引用号前缀和引脚类型 |

**第二件:兼容真实网表的写法(读宽容)。**
我们的导入器原来只认自己导出的格式,读 KiCad 的网表会失败,原因有两个:
- 正则里写死了**单个空格**:`(comp (ref "U1")`,而 KiCad 是**每个字段单独一行** → 改成 `\s+`
- 写死了 **U 前缀**:真实网表里是 `R1`、`C3` 混排 → 改成通用前缀,并按"前缀+编号"建映射;
  同号不同前缀(比如 R1 和 C1)会自动分配不冲突的编号

**第三件:用 KiCad 的真实网表做互操作测试。**
单元测试里内嵌了 KiCad 真实输出的缩略版(保留换行缩进、R 前缀、1 起引脚号这三处"坑"),
断言我们能把元件、网络、引脚映射全部读对。

> **老实说**:最后一公里的"在 KiCad 图形界面里点导入、看到元件和网络出现在 PCB 上"
> 只能人工做一次 —— KiCad 没有提供命令行/脚本的网表导入接口。
> 但格式已按 KiCad 自己的输出对齐、并用真实网表验证了双向解析,导入失败的概率很低。

## 3.7 导出 KiCad 原理图(.kicad_sch)——让"能被 PCB 软件加载"看得见

**为什么还要加这个**:KiCad 6 以后的"正统"流程是

```
原理图 --(工具 → 从原理图更新 PCB / 快捷键 F8)--> PCB
```

从文件导入网表虽然还在(PCB 编辑器 → 文件 → 导入 → 网表),
但原理图这条路更直观:打开就能看见元件符号和连线,演示/答辩时一目了然。

**实现要点(两个坑)**:

1. **坐标精度**:导出的"引脚位置"和"导线端点"必须在 KiCad 里是**同一个点**,
   差一点点就连不上。做法是全程用**纳米整数**计算,打印时按 6 位小数输出
   (1px = 0.127mm = 127000nm,所有偏移都是整数,打印无损)。
   引脚和导线端点都由同一组整数算出,天然严丝合缝。

2. **符号库的命名规则**:`lib_symbols` 里每个符号内部的"单元"名要用**短名**
   (`SW_0_1`),不能带库前缀(`MyEDA:SW_0_1`)—— 写错 KiCad 直接报"加载原理图失败"。
   这个错误没有任何提示信息,只能靠和 KiCad 自己导出的文件对比才能发现。

**怎么验证它真的能被 KiCad 用?** 用 KiCad 自己的命令行工具回读:

```bash
# 1) 我们把电路导出成 KiCad 原理图
test_sim.exe --export-kicad-sch 样例/半加器.eda 样例/半加器.kicad_sch
# 2) 让 KiCad 加载这份原理图,并导出它自己算出来的网表
kicad-cli sch export netlist --format kicadsexpr -o out.net 样例/半加器.kicad_sch
# 3) 对比两个网表的"网络集合"
```

实测结果(半加器):

```
我们导出的网络数: 4
    [(U1,1), (U3,1), (U4,1)]     ← 开关A → 异或门输入1 + 与门输入1(扇出)
    [(U2,1), (U3,2), (U4,2)]     ← 开关B → 异或门输入2 + 与门输入2
    [(U3,3), (U5,1)]             ← 异或门输出 → 灯(和)
    [(U4,3), (U6,1)]             ← 与门输出   → 灯(进位)
KiCad 提取的网络数: 4
    [(U1,1), (U3,1), (U4,1)]
    [(U2,1), (U3,2), (U4,2)]
    [(U3,3), (U5,1)]
    [(U4,3), (U6,1)]
两边完全一致
```

**这就是"能被 PCB 软件加载"的硬证据**:不是"我们觉得格式对",
而是 KiCad 自己把我们的原理图读进去、算出连通关系,结论和我们一模一样。

界面里也有入口:**文件 → 导出 KiCad 原理图(.kicad_sch)**。

## 3.8 从网表到 PCB:把最后一步走通(封装这个大坑)

前面 3.5 节证明了"网表能被 KiCad 读"。但真去 KiCad 里导入时,会撞上这个:

```
错误: 无法添加 U6 (没有分配封装)。
总计告警: 0   错误: 6
```

**"封装"(footprint)是什么**:网表只描述"谁和谁相连",但元件在电路板上是什么形状、
有几个焊盘、每个焊盘在哪 —— 这些由"封装"描述。没有封装,PCB 软件不知道把元件
摆在板子上的什么位置、更没法布线。

**坑在哪里**:我们以为把封装写进 `(fields (field (name "Footprint") "..."))` 就够了,
其实 KiCad 的导入程序读的是**紧跟 `(value ...)` 的那个独立的 `(footprint "...")`**:

```
(comp (ref "U1")
  (value "SW")
  (footprint "Button_Switch_THT:SW_PUSH_6mm")   ← 这个才是导入时读的
  (fields
    (field (name "Footprint") "Button_Switch_THT:SW_PUSH_6mm")  ← 这份是给人看的
    ...
```

这个结论不是猜的:让 KiCad 自己导出一份"指定了封装"的原理图网表,逐字段对比就能看出来。

**我们的做法**:给元件加默认封装(都是 KiCad 自带标准库里的真实封装):

| 元件 | 默认封装 | 为什么 |
|---|---|---|
| 与/或/非/异或门 | `Package_DIP:DIP-14_W7.62mm` | 逻辑门当成 14 脚 DIP(类似 74 系列芯片) |
| 开关 | `Button_Switch_THT:SW_PUSH_6mm` | 轻触按键,2 个焊盘 |
| 指示灯 | `LED_THT:LED_D5.0mm` | 5mm 直插 LED |

**导入结果**(截图在 `docs/images/screenshots/KiCad导入网表-0错误.png`):

```
总计告警: 28   错误: 0
```

28 个告警都是同一种无害提示:"DIP-14 有 14 个焊盘,而我们的门只有 3 个引脚,
多出来的焊盘 4~14 找不到对应引脚" —— 空着不用就行。

**点"更新 PCB"之后**(截图 `docs/images/screenshots/KiCad生成的PCB已保存.png` 的状态栏):

```
焊盘 40   过孔 0   走线段 0   网络 4   未布线 8
文件 '...\half_adder.kicad_pcb' 已保存。
```

- **网络 4** = 我们导出的 4 个网络原样进了 PCB
- 保存出来的 `half_adder.kicad_pcb` 里,可以查到 **6 个封装、40 个焊盘、U1~U6 全部位号**,
  以及我们命名的网络 `Net-(U1-Pad1)`、`Net-(U3-Pad3)` 等 —— 名字都是我们生成的
- "未布线 8"是正常的:网络已经连好"逻辑上该接谁",还没画实际的铜线(布线是 PCB 工程师的活)

**这一步的意义**:任务要求的"导出标准网表文件,该文件能够被 PCB 软件加载,
进行后续设计流程"到这里是**完整闭环**了 —— 从我们画的电路,一路走到 KiCad 里
摆好封装的 PCB 板子。

> 顺带记两个自动化技巧(用来做这套验证的):
> ① 中文菜单不好用坐标点 → 用 `GetMenu/GetSubMenu/GetMenuItemID` 遍历菜单树,
>    按文字找到菜单项的 **ID**,再 `PostMessage(WM_COMMAND, id)` 触发;
> ② 文件路径框不能用键盘打(会被输入法截获)→ 用**剪贴板 + Ctrl+V** 输入。

## 4. 调试故事(比代码更值钱的方法论)

### 4.1 单元测试抓到了真 bug

写自定义元件时,单元测试报告:

```
[FAIL] ROUNDTRIP type  got=0 want=1
```

意思是"自定义元件存盘再读回来,类型变了"。查代码发现 `GateTypeName()` 里漏了 `GATE_CUSTOM` 分支:

```cpp
inline wxString GateTypeName(GateType t) {
    if (t == GATE_AND) return "AND";
    ...
    if (t == SW_INPUT) return "SW";
    return "LED";        // ← 自定义元件掉进这里了!存盘变成了 "LED"
}
```

**手点界面很难发现这个 bug**(要"存一个自定义元件 → 重开 → 仔细观察类型"),但单元测试 1 秒就抓到了。这就是"把逻辑做成纯函数 + 写测试"的回报。

### 4.2 二分注释法

界面出问题时(比如弹了个莫名其妙的断言框),**不要盯着代码干看**:
把可疑代码**注释掉一半**,重新编译运行,看问题还在不在 —— 在,说明问题在另一半;不在,说明就在这一半。
再对那一半重复,两三轮就能锁定到具体几行。

### 4.3 两个坑(踩了很久才想明白)

**坑一:模态对话框会"禁用"主窗口。**
我们测试时不小心让一个"另存为"对话框一直开着,之后所有的模拟点击都**静默失效** ——
因为 Windows 的模态对话框会把主窗口禁用,点击根本送不进去。
排查了很久才发现。**教训**:看到"点击没反应"先想想"是不是有对话框开着"。

**坑二:DPI 缩放的坐标换算。**
这台电脑桌面缩放是 **150%**。而我们的程序是"DPI 不感知"的老式应用,于是:
- 自动化脚本里取的窗口矩形是**物理像素**;
- 程序内部使用的坐标是**逻辑坐标 = 物理像素 ÷ 1.5**;
- 鼠标点击用物理坐标,程序收到的客户区坐标 = (物理 − 窗口原点) ÷ 1.5。

不换算,点击就"偏"了,还会出现"元件明明在文件里却看不到"——
因为窗口设成 1800×1150 物理时,程序内部只有 1200×767 逻辑,画布只有 754 宽,
坐标 480 的元件刚好在可见区,坐标 700 的就被裁到窗口外了。

**普通人用不到这个知识,但你要做 GUI 自动化测试/被老师问"为什么点击不准"时,这就是答案。**

## 6. 数据文件长什么样

```json
{
  "components": [
    {"id":1,"type":"SW","x":200,"y":250,"state":1,"name":"","truth":0},
    {"id":3,"type":"CUSTOM","x":480,"y":340,"state":0,"name":"MYAND","truth":8},
    {"id":5,"type":"LED","x":700,"y":340,"state":0,"name":"","truth":0}
  ],
  "wires": [
    [1,0,3,0],
    [3,2,5,0]
  ]
}
```

- `components`:每个元件一行,id 是编号,type 是类型,xy 是坐标。
- `wires`:每根连线四个数 `[起点元件, 起点引脚, 终点元件, 终点引脚]`。
- 引脚编号约定:与/或/非/异或/与非/或非门 `0=上输入 1=下输入 2=输出`;非门 `0=输入 1=输出`;开关/灯只有一个引脚(编号 0)。

## 连线预览的绘制优化

`DrawingCanvas::OnPaint()` 使用双缓冲，并把背景擦除交给绘制过程，避免先清空屏幕再逐个绘制造成闪烁。网格、已完成的连线和元件缓存在位图中；只有电路内容、选择、仿真状态或窗口尺寸发生变化才重建。

鼠标移动仅更新预览终点，刷新旧线和新线的覆盖区域；刷新请求异步处理，可以合并密集的鼠标事件。第一下点中引脚时将终点初始化到起点，Esc 和切换工具会清除预览，避免跳线和残影。

交互回归测试 `MyEDA/test/test_canvas.cpp` 在真实画布上比较像素，覆盖起点初始化、取消、切换工具、四向移动、完成连线、撤销重做和窗口缩放。它需要已解锁且无遮挡的 Windows 桌面，会短暂显示测试窗口，运行时不要移动鼠标或切换窗口。先完成正常构建，然后在能找到 CMake 的终端中执行：

```powershell
cmake --build MyEDA/build --config Debug --target test_canvas
.\MyEDA\build\Debug\test_canvas.exe
```

测试未纳入日常无窗口的 `build.bat`；64 项逻辑与文件测试仍由原入口运行。像素回归通过不代表测量了所有机器上的帧率，流畅度仍需在实际电路规模下体验。

| B 绘图与编辑 | `MyEDA/src/editor/`、`core/Component.h`、`core/WireRouting.h` | 元件、连线、拐点和文档状态 |
| C 文件与连接 | `MyEDA/src/file/`、`core/CircuitValidation.h` | 存档字段、连接规则、网表格式 |
| D 仿真与集成 | `MyEDA/src/sim/`、`MyEDA/test/`、构建脚本 | 逻辑行为、验收用例和发布版本 |

建议 main 只保留编译和测试通过的版本；每个具体任务建一个功能分支，经其他组员检查后由组长合并。分工是协作约定，不限制其他人阅读代码。

完整职责和期末贡献记录见 `docs/课程资料/四人分工与贡献说明.md`。

## 二、开始新任务

先保存电路、关闭 MyEDA，用 `git status` 确认工作区干净；有修改时先妥善处理，不直接切换分支。以下以 `feature/a-property-panel` 为例，请换成自己的任务名称：

```powershell
git status
git switch main
git pull --ff-only
git switch -c feature/a-property-panel
```

## 三、修改、验证、提交

1. 修改自己的模块；改动公共数据结构或接口前通知使用它的组员。
2. 双击 `build.bat`，确认编译与测试通过；涉及界面时还要手动操作验证。
3. 用下面的命令查看改动，按实际文件路径提交，不把 build 目录、个人电路草稿和临时截图混入提交。

```powershell
git status
git diff
git add MyEDA/src/ui/MyFrame.cpp
git commit -m '完善元件属性显示'
git push -u origin feature/a-property-panel
```

`git add` 后面的文件只是示例，需要包含完成该改动所需的全部相关文件。首次 `push -u` 建立上游；之后可用 `git push`。

在 GitHub 上创建从该分支到 main 的 Pull Request，说明改了什么、怎么验证，由另一位组员检查，组长合并。不要强制推送共享分支。

## 四、更新自己的工作区

- **当前分支已设置上游，且没有本地修改：**双击 `update-and-run.bat`，会拉取该分支、编译、测试并启动。
- **正在修改代码，只想试运行：**双击 `build.bat`，不需要先拉取或提交。
- **想获取 main 上其他人的成果：**在工作区干净时执行以下命令。功能分支的“更新”不会自动包含 main 的新提交。

```powershell
git fetch origin
git merge origin/main
```

合并后重新运行 `build.bat` 并检查功能，再推送自己的分支。团队默认使用快进拉取和显式合并；不要把 `git pull --rebase` 当成所有情况下通用的更新命令。

## 五、遇到冲突或无法快进

`git pull --ff-only` 失败时不会自动替你解决分叉。先运行：

```powershell
git status
git log --oneline --graph --decorate -10
```

把输出交给负责合并的组员，确认该合并哪个分支。发生 merge 冲突时，和相关文件负责人一起修改冲突文件，验证后 `git add` 对应文件，再 `git commit`。若决定取消当前合并，可使用 `git merge --abort`。

不要为让更新成功而直接执行 `git reset --hard`、`git clean -fd` 或强制推送；这些不是普通更新步骤。

## 六、文档同步与演示版本

- 编辑 `docs/` 下分篇文档，不手改根目录的《项目完整教程》。
- 更新教程后，在根目录运行下面两条命令，并把源文档和生成的合集一起提交：

```powershell
python .\tools\merge_docs.py
python .\tools\merge_docs.py --check
```

- 功能变化后复核截图、速查卡和演示步骤；文本合集更新不会自动重绘图片。
- 答辩前由一人统一编译、测试并打包程序、`res` 目录和示例，记录提交号与依赖版本。其他人用同一份包演示，避免版本不一致。
- 所有分工、调试经历和测试结论应按实际完成情况填写，模板不能代替验证记录。
