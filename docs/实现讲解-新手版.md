## 0. 项目全景(先花 30 秒看懂全局)

**我们做的是什么**:一个电路原理图编辑器,用户可以画逻辑电路、仿真验证、导出网表给 PCB 软件。

**核心思想(全项目只有这一条主原则)**:

> **数据是核心,界面只是把数据"画"出来。**

整个项目就围绕两个数据结构转:

```cpp
struct Component {          // 一个元件
    GateType type;          //   什么门(与/或/非/异或/与非/或非/开关/灯/自定义)
    int x, y;               //   画在哪儿
    int id;                 //   编号(显示成 U1、U2...)
    bool state;             //   开关的开/关
    wxString customName;    //   自定义元件的名字
    int truth;              //   自定义元件的真值表
};

struct Wire {               // 一根连线
    int comp1, pin1;        //   起点:哪个元件、哪个引脚
    int comp2, pin2;        //   终点
    wxVector<wxPoint> bends; // 中间拐点(可选)
};
```

**所有功能都是围绕"元件列表 + 连线列表"这两个数据转的**:
- 绘图区 = 把数据画出来
- 存档 = 把数据写成 JSON
- 网表 = 把数据转成 KiCad 格式
- 仿真 = 根据数据算逻辑

## 2. 九种元件类型(任务3)

当前支持 9 种元件,每种都有独特的符号绘制和仿真逻辑:

| 类型 | 枚举 | 符号形状 | 引脚数 | 仿真行为 |
|---|---|---|---|---|
| 与门 AND | `GATE_AND` | D 形 | 3 | 输出 = 输入1 ∧ 输入2 |
| 或门 OR | `GATE_OR` | 弯月形(折线) | 3 | 输出 = 输入1 ∨ 输入2 |
| 非门 NOT | `GATE_NOT` | 三角+小圆 | 2 | 输出 = ¬输入 |
| 异或门 XOR | `GATE_XOR` | 双弧弯月 | 3 | 输出 = 输入1 ⊕ 输入2 |
| 与非门 NAND | `GATE_NAND` | D形+小圆 | 3 | 输出 = ¬(输入1 ∧ 输入2) |
| 或非门 NOR | `GATE_NOR` | 弯月+小圆 | 3 | 输出 = ¬(输入1 ∨ 输入2) |
| 开关 SW | `SW_INPUT` | 绿色方框"1"/"0" | 1 | 输出 = 自身状态 |
| 指示灯 LED | `SW_LED` | 圆形(亮红/灭白) | 1 | 显示来源信号 |
| 自定义 CUSTOM | `GATE_CUSTOM` | 淡黄方框+名字 | 3 | 查自身真值表 |

**加一种新元件只需在 4 个注册点各加一行**(注册表模式):
①`Component.h` 枚举+引脚坐标 ②`CircuitFile.h` 名字表+正则 ③`DrawGate()` 绘制 ④`SimulateCircuit()` 仿真逻辑

### 引脚坐标与网格吸附

所有引脚坐标由 `GetPinPos()` 从元件位置推导,**并做 10 像素网格吸附**(`SnapGrid()`)。
这意味着引脚永远对齐网格,画出来的电路图整洁专业。

### 连线的 L 形自动路由

两根引脚不在同一行/列时,`WireRouting.h` 的 `BuildWirePath()` 会自动生成
L 形路径(先走一段水平,再垂直,最后到达目标),而不是画斜线——
这就是真实 EDA 软件的走线方式。

## 3. 绘图区交互(任务2/3/4 核心)

`DrawingCanvas` 继承 `wxPanel`,处理五种鼠标/键盘事件:

### 放置元件
点树/工具栏选类型 → 画布空白处点击 → `components.push_back()` → `Refresh()`

### 命中测试(`HitTest`)
从后往前遍历(后画的在上层),判断鼠标坐标是否落在元件包围盒内。
引脚命中(`HitPin`)用距离判断(引脚周围 9 像素)。

### 拖动(支持整组)
按下时记下**每个选中元件相对鼠标的偏移**,移动时同步平移。
松手时比较快照,**只在真的移动了才记一步撤销**。

### 连线(两步状态机)
点第一个引脚记住起点 → 移动时画虚线预览 → 点第二个引脚存入 `Wire`。
拐点支持:连线可走多段拐点,存在 `Wire.bends` 里。

### 删除(级联)
删除元件时同时删掉它身上的连线,避免悬空引用。

### 撤销(快照式)
改动前把电路序列化成 JSON 文本压栈(最多 100 步),撤销就是读回旧文本。
**一份代码覆盖放置/删除/拖动/连线/粘贴所有操作。**

### 双缓冲绘制
为了防止拖动时闪烁,`DrawingCanvas` 使用双缓冲:
静态内容(网格+元件+连线)缓存到一张内存位图 `sceneBitmap`,
只有内容变化时才重建(`InvalidateScene()`),
预览线(橡皮筋)用 `wxPaintDC` 直接叠加在上面。

## 4. 文件存档与网表(任务5)

### 工程文件 `.eda`(JSON)

```json
{
  "components": [
    {"id":1,"type":"SW","x":200,"y":250,"state":1,"name":"","truth":0},
    {"id":3,"type":"CUSTOM","x":480,"y":340,"state":0,"name":"MYAND","truth":8}
  ],
  "wires": [
    [1,0,3,0],
    [3,2,5,0]
  ],
  "customGates": [
    {"name":"MYAND","truth":8}
  ]
}
```

**写严格读宽容**:新增字段用可选解析(`(?:...)?`),旧文件仍可打开。

### 网表 `.net`(KiCad S 表达式)

导出时做了三件对齐 KiCad 真实格式的事:
1. **网络归并**(`BuildNets` 并查集):一个输出接多个输入(扇出)时,这些引脚归为同一个网络
2. **封装**:每个元件带默认封装(门→DIP-14、开关→按键、灯→LED),否则 KiCad 报错
3. **引脚编号从 1 开始**(与 PCB 焊盘编号一致)

## 5. 逻辑仿真(任务6)

**算法:迭代传播**

```
1. 初始:开关输出 = 自身状态,门输出全部 = 0
2. 重复"元件数 + 2"轮:
   每个门读输入引脚的来源值 → 算出自己的新输出
3. 信号从开关传播到最远的灯(组合逻辑无环,必定收敛)
```

**自定义元件**:输入组合编号 `i = A*2 + B`,取 `truth` 的第 i 位。

**仿真中的视觉反馈**:高电位导线红色、低电位黑色;LED 亮红/灭白。

## 6. 与 KiCad 对接

### 网表导出
- 格式:KiCad 6+ S 表达式,含 `(design) (components) (libparts) (nets)` 四段
- 验证:让 KiCad 自己(`kicad-cli sch export netlist`)导出参考网表,逐字段比对
- 实测:导入 0 错误,生成 6 封装/40 焊盘/4 网络的 PCB

### 原理图导出
- 格式:`.kicad_sch`(纳米精度坐标,1px = 0.127mm = 127000nm)
- 引脚位置和导线端点由同一组整数算出,保证 KiCad 里严丝合缝
- 实测:KiCad 从我们生成的原理图中提取的 4 个网络与我们的网表完全一致

## 7. 测试体系

**单元测试(不开窗口,秒级验证)**:

```
test_sim.cpp:     51 项(门逻辑/自定义真值表/存档往返/网表往返/扇出归并/KiCad 互操作)
test_canvas.cpp:  16 项(撤销/重做/窗口缩放/连线恢复)
合计:             67 项,全部 PASS
```

**单元测试的价值**:靠它抓到了至少 2 个真 bug——
① 存盘函数漏了自定义元件分支(自定义元件存盘后变成 LED)
② 网表扇出归并逻辑的跨网络错配
这些 bug 手工测试很难发现,但纯函数测试 1 秒就能定位。

**GUI 自动化**:用 PowerShell + `PostMessage` 模拟真实操作,
再比对保存出来的文件内容(坐标级证据,不是"看起来对")。

## 8. 与 PCB 软件的对接

**从我们的电路到 KiCad PCB 的完整流程**:

```
MyEDA 画电路 → 导出网表(.net) → KiCad PCB 编辑器 → 文件→导入→网表 → 更新PCB
                或
MyEDA 画电路 → 导出原理图(.kicad_sch) → KiCad 打开 → F8 更新 PCB
```

实测:KiCad 10.0 导入我们网表后,**0 错误**,生成 6 封装/40 焊盘/4 网络的 PCB。
截图在 `docs/样例/` 目录。
