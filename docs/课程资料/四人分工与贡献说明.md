## 一、项目目标与总体分工

项目采用 C++17、wxWidgets 和 CMake，实现“搭建数字电路 → 连线与编辑 → 逻辑仿真 → 工程保存 → 导出 KiCad 文件”的基本流程。小组按功能模块划分主要责任，同时通过公共数据模型和联合验收完成集成。

| 角色 | 主要责任 | 核心交付成果 | 协作责任 |
|---|---|---|---|
| A：界面与元件库 | 主窗口、菜单/工具栏、属性表、自定义元件对话框和界面反馈 | 可操作的界面、元件库入口、属性联动、明确的操作提示 | 与 B 对接编辑命令和元件库模型操作，与 D 验证交互流程 |
| B：绘图与编辑 | 画布渲染、网格吸附、直角折线、选择与编辑、撤销重做、缩放平移 | 可编辑的原理图画布及稳定的交互状态 | 与 C 统一连接数据和校验入口，与 A 对接界面刷新，与 D 完成像素和操作回归 |
| C：文件与电路连接 | 工程存档、结构化 JSON 校验、连接合法性规则、网表和 KiCad 原理图对接 | 可保存重开的工程、可靠的导入导出和连接检查 | 与 B 确认引脚/拐点格式，与 D 验证存档往返和网表导入后的仿真 |
| D：仿真、测试与集成 | 组合逻辑计算、自动化测试、构建脚本、演示版本验证与发布资料 | 正确的仿真结果、测试记录、可运行的演示版本 | 与 A/B/C 联合排查问题，汇总证据、版本和测试结果 |

分工按“谁对该模块的结果负责”划分。公共接口、跨模块故障和最终验收由相关成员共同完成，不能简单按文件数量或代码行数判定贡献。

## 二、成员具体职责与验收标准

### A：用户界面与元件库交互

**主要工作**

1. 组织主窗口中的菜单、工具栏、元件库树、绘图区、属性表和状态栏，使常用功能有清晰入口。
2. 维护工具栏 SVG 图标、文字布局和资源加载，使不同显示缩放下的图标可辨认。
3. 实现元件属性显示与选择状态联动，显示元件类型、坐标、开关状态、真值表和仿真输出。
4. 负责自定义元件的新建、编辑、删除对话框，检查重名和输入内容，并调用画布模型接口。
5. 负责保存提醒和用户操作反馈，将文件异常、非法连线、仿真中的编辑限制等信息展示给使用者。

**主要代码与接口**

| 位置 | 负责内容 |
|---|---|
| `MyEDA/src/ui/MyFrame.h`、`MyFrame.cpp` | 主窗口、菜单事件、工具栏、属性表、文件对话框和状态栏 |
| `MyEDA/src/ui/CustomDialog.h` | 自定义元件定义与管理对话框 |
| `MyEDA/src/ui/MyApp.cpp` | 程序入口与启动文件参数 |
| `MyEDA/src/res/` | 工具栏 SVG 图标及 PNG 兼容资源 |
| 与 B 的接口 | `SetSelectionCallback()`、`SetHintCallback()`、`AddCustomDefinition()`、`EditCustomDefinition()`、`DeleteCustomDefinition()` |

**验收标准与证据**

- 窗口布局完整；菜单和工具栏能触发对应操作。
- 选择元件或连线后，属性表和状态提示与实际对象一致。
- 自定义元件改名、修改真值表、删除和撤销后，元件库树与画布内容一致。
- 未保存修改时关闭或切换工程，会提示保存；用户取消后保留当前状态。
- 提供界面截图、对话框操作记录、相关修改或调试记录。

**期末个人报告重点**：界面布局方式、事件绑定、回调联动、元件库交互，以及一次本人参与排查的界面状态问题。

### B：绘图画布与编辑交互

**主要工作**

1. 维护元件和连线在画布上的表示，绘制逻辑门、开关、指示灯、引脚和选择状态。
2. 实现网格显示与吸附，支持多拐点直角连线和预览，并正确处理完成、取消和工具切换。
3. 实现元件选择、框选、整组移动、复制粘贴及内部连线复制，支持单独选中和删除连线。
4. 维护撤销重做、编辑快照和未保存状态；将自定义元件库变化纳入相同的文档状态管理。
5. 使用双缓冲、静态画布缓存和预览区域刷新减少闪烁；实现滚轮缩放、中键平移和视图复位。

**主要代码与接口**

| 位置 | 负责内容 |
|---|---|
| `MyEDA/src/editor/DrawingCanvas.h`、`DrawingCanvas.cpp` | 绘制、鼠标键盘交互、编辑状态、剪贴板和撤销重做 |
| `MyEDA/src/core/WireRouting.h` | 网格吸附与水平/垂直路径生成 |
| `MyEDA/src/core/Component.h`（共同维护） | 元件、连线、拐点、元件定义和引脚坐标 |
| 与 A 的接口 | 编辑命令、属性查询、选择回调、提示回调和视图复位 |
| 与 C 的接口 | `Component`、`Wire`、`CustomDef` 及连接校验函数 |

**验收标准与证据**

- 连线和拐点吸附网格，取消操作后无预览残影。
- 复制电路片段时保留内部连线和拐点，不复制通向片段外部的连接。
- 删除单线不会删除两端元件，撤销后连接恢复。
- 缩放和平移后命中测试、放置和连线使用正确的工程坐标；单纯改变视图不产生工程修改。
- 提供编辑前后 `.eda` 文件、交互截图、画布回归测试记录和性能改进说明。

**期末个人报告重点**：交互状态如何切换、坐标转换、直角路径表示、快照撤销，以及闪烁或残影问题的定位过程。

### C：工程文件、连接校验与 KiCad 对接

**主要工作**

1. 维护 `.eda` 数据格式，保存元件、连接、拐点与自定义元件定义，兼容已有有效工程。
2. 进行结构化 JSON 解析和字段校验，处理字符串转义、编号和引脚引用；读取失败时保留当前电路。
3. 维护连接方向和合法性规则，统一输出到输入的方向，拒绝重复驱动、无效引脚和组合逻辑反馈环。
4. 导出及解析 KiCad 网表，进行网络归并；导入数字电路时按驱动输出向各输入重建连接。
5. 导出 KiCad 原理图，维护示例和格式参考，记录可复现的对接结果与功能范围。

**主要代码与接口**

| 位置 | 负责内容 |
|---|---|
| `MyEDA/src/file/CircuitFile.h` | 工程序列化、解析、读取和保存 |
| `MyEDA/src/file/Json.h` | JSON 结构和字符串解析 |
| `MyEDA/src/file/NetlistExport.h` | 网表导出、解析、网络归并和扇出重建 |
| `MyEDA/src/file/KicadSchExport.h` | KiCad 原理图格式输出 |
| `MyEDA/src/core/CircuitValidation.h` | 引脚方向、重复输入和反馈环校验 |
| `examples/half_adder/`、`examples/reference/` | 可编辑样例和参考网表 |

**验收标准与证据**

- 工程保存后重新打开，元件、连线、拐点和自定义定义保持一致。
- 损坏文件、非法引用和不适合作为逻辑电路导入的网表被拒绝，原电路不丢失。
- 反向点击输入和输出也能形成正确的电气连接。
- 半加器网表导出再导入后，四种输入组合的仿真结果保持正确。
- 提供存档往返记录、异常输入样例、导出文件、KiCad 操作截图及所用软件版本。

**期末个人报告重点**：数据格式选择、无损失败处理、连线与网络的区别、扇出重建，以及 KiCad 对接中遇到的格式问题。

### D：逻辑仿真、质量验证与版本集成

**主要工作**

1. 维护组合逻辑仿真算法，计算内置门和真值表自定义元件的输出，联动导线电平和指示灯状态。
2. 编写与维护逻辑、存档、网表、非法输入和反馈检查，验证模块间的数据一致性。
3. 与 A/B 合作维护画布交互测试，验证预览、拐点、单线编辑、元件库状态及视图操作。
4. 维护 CMake、构建脚本和更新启动入口，保证失败时停止后续步骤，不运行过期的测试程序。
5. 组织半加器端到端验收，整理测试记录、演示清单和发布包；复核报告、截图与演示版本的一致性。

**主要代码与接口**

| 位置 | 负责内容 |
|---|---|
| `MyEDA/src/sim/Simulation.h` | 组合逻辑传播、输入来源及指示灯结果 |
| `MyEDA/test/test_sim.cpp` | 逻辑与文件测试、网表工具模式 |
| `MyEDA/test/test_canvas.cpp` | 画布与交互回归测试 |
| `MyEDA/CMakeLists.txt` | 构建目标和依赖配置 |
| `build.bat`、`build.ps1`、`update-and-run.bat`、`update-and-run.ps1` | 构建、测试与更新启动流程 |
| `tools/test_build_failure.py` | 构建失败保护检查 |

**验收标准与证据**

- 半加器输入为 00、01、10、11 时，和输出依次为 0、1、1、0，进位依次为 0、0、0、1。
- 每次发布前运行相关测试，记录结果和构建配置；测试通过不能代替现场功能检查。
- 关键回归能够复现原问题，并验证修复后行为，特别是导入后仿真、文件保护和元件库状态。
- 演示包能在实际展示电脑上提前启动，包含程序、资源、示例、操作说明和测试记录。
- 提供测试日志、问题清单、版本记录和联合验收记录。

**期末个人报告重点**：仿真原理、用例选择、失败复现与回归验证、构建失败保护，以及版本集成过程。

## 七、当前进展与后续范围

当前本地版本已具备界面、元件库、网格直角连线、编辑、组合逻辑仿真、工程存档和 KiCad 文件对接；近期补充了连线校验、内部连线复制、单线删除、文件保护、元件库撤销以及缩放平移复位。

最近一次本地 Release 验证记录为 **64 项逻辑／文件检查、42 项画布／交互检查通过**，并包含半加器网表导入后的四种输入组合。此结果仅对应本次验证版本；期末应以最终提交版本重新运行测试并保留日志。

已准备的资料包括 `docs/课程资料/阶段展示检查清单.md`、半加器工程与 KiCad 样例，以及本地 `dist/` 下的演示包。未提交的本地修改不会自动出现在其他组员的工作区，团队验收前应统一代码版本。

当前 PCB 样例用于文件对接展示，尚未完成实际布线和制板验证；软件仿真范围为无环组合逻辑，没有实现时序器件和模拟电路。相关内容若不是课程要求，应在“不足与后续工作”中说明；若课程另有要求，再单独安排任务和责任人。

## 八、使用方式

1. 现在用第一至五节确认角色和工作边界，按第六节持续记录实际任务。
2. 阶段展示前按《阶段展示检查清单》联合验收，各人讲清本模块与其他模块的接口。
3. 期末替换 A/B/C/D 的姓名和学号，填写最终分工、实际成果及证据。
4. 全组确认内容后，将分工表和个人贡献记录整理进课程报告；演示讲稿继续使用《分工与答辩手册》。

封装功能已经实现，以下是建议验收分工，实际作者、提交和工时仍需四人据实填写。
